Theoretical Foundations

📚 Learn the Disk Scheduling Algorithms

Comprehensive operational mechanics, architectural trade-offs, starvation vulnerabilities, and pseudocode implementations.

FCFS First-In First-Out

First-Come First-Serve

Requests are serviced strictly in arrival order. Completely fair and simple, but suffers from severe head oscillation across distant tracks (the wild arm swing problem).

Pros: Zero starvation, fair, minimal CPU scheduling overhead.
Cons: Unoptimized seek distance; high average waiting time.
Time Complexity: O(N) Starvation: None
View Pseudocode 
function FCFS(requests, head):
    for req in requests:
        seek_to(req)
        head = req
SSTF Greedy Selection

Shortest Seek Time First

Selects the pending request closest to current head position. Minimizes immediate seek movement, but can cause distant cylinders to starve indefinitely under continuous arrivals.

Pros: Substantially reduces average seek time and increases throughput.
Cons: High starvation risk; directional oscillation; queue scanning cost.
Time Complexity: O(N²) greedy Starvation: High
View Pseudocode 
function SSTF(requests, head):
    while requests remain:
        nearest = min(requests, key=distance_from(head))
        seek_to(nearest)
        remove nearest from requests
        head = nearest
SCAN Elevator Sweep

SCAN (Elevator Algorithm)

Disk arm sweeps continuously in one direction servicing requests until it hits the physical disk boundary (0 or Max-1), then reverses direction and sweeps back.

Pros: Predictable bounds, no starvation, smooth arm movement.
Cons: Travels all the way to disk boundaries even when no requests exist there.
Time Complexity: O(N log N) Starvation: None
View Pseudocode 
function SCAN(requests, head, direction, disk_size):
    sweep in direction servicing requests
    advance to physical disk boundary (0 or Max-1)
    reverse direction and sweep back servicing remainder
C-SCAN Circular Sweep

Circular SCAN

Sweeps in a single direction to the disk boundary, then performs an immediate circular reset jump to the opposite boundary without servicing requests on the return journey.

Pros: Uniform waiting time distribution; treats cylinders as circular ring.
Cons: Circular jump overhead; boundary travel even when unnecessary.
Time Complexity: O(N log N) Starvation: None
View Pseudocode 
function CSCAN(requests, head, direction, disk_size):
    sweep in direction to boundary
    jump to opposite boundary without servicing
    resume sweep in original direction
LOOK Adaptive Reversal

LOOK Algorithm

An optimized elevator algorithm. The head looks ahead in the current direction. When no further requests remain ahead, it reverses immediately without traveling to the disk boundaries.

Pros: Eliminates wasted travel to boundaries; lower total seek than SCAN.
Cons: Waiting time varies by arm position; requires look-ahead check.
Time Complexity: O(N log N) Starvation: None
View Pseudocode 
function LOOK(requests, head, direction):
    sweep in direction until last pending request
    reverse direction immediately
    sweep opposite direction until final request
C-LOOK Circular Adaptive

Circular LOOK

Circular variant of LOOK. Sweeps in one direction until the last request in that direction, then jumps directly to the furthest request on the opposite side without touching boundaries.

Pros: Combines uniform waiting time of C-SCAN with boundary avoidance of LOOK.
Cons: Jump overhead; slight directional bias.
Time Complexity: O(N log N) Starvation: None
View Pseudocode 
function CLOOK(requests, head, direction):
    sweep in direction until last request in direction
    jump directly to furthest opposite request
    resume sweep in original direction
Storage Architecture

Mechanical HDD Seek Time vs Modern Solid State Drives

Traditional Hard Disk Drives (HDDs) store data magnetically across spinning platters. Accessing any data sector requires three sequential physical steps:

1. Seek Time (3–15 ms): The physical arm moves to align with the destination cylinder track. Disk scheduling algorithms directly optimize this mechanical phase.
2. Rotational Latency (2–8 ms): Waiting for the magnetic platter to rotate the targeted sector under the head.
3. Transfer Time (<1 ms): Electrical transfer of bytes from platter surface to disk controller cache.
Why is this taught today if we use SSDs?

Solid State Drives (SSDs) and NVMe storage use electronic flash memory with zero moving parts, making mechanical seek time irrelevant. However, understanding disk scheduling teaches foundational Operating Systems concepts: queue reordering, starvation vs fairness trade-offs, and batch optimization. Modern OS kernels (like Linux BFQ and Kyber) adapt these very principles to optimize block I/O bandwidth, write wear-leveling, and multi-threaded QoS.
